## Phase 5 — Full Virtual Machine Engine (QEMU `11.1.3`)

- **Independent QEMU `11.1.3` subsystem decoupled from PRoot & Wine.** Full hardware virtualization/emulation lives in `rust/crates/vm` (`androidpc-vm`), isolated in `<filesDir>/vms/<vm_id>/`, with its own VNC port range (`5910+`) and QMP range (`4444+`), so VM crashes, pauses, or deletion never affect PRoot Ubuntu/Debian containers, XFCE `:1` (`5901`), or Phase 4 Wine prefixes. [Virtualization architecture](VIRTUALIZATION_ARCHITECTURE.md)
- **Multi-threaded TCG primary backend with opportunistic `/dev/kvm` and honest AVF reporting.** Because Android restricts `MANAGE_VIRTUAL_MACHINE` (AVF/pKVM) to `@SystemApi` privileged apps and typically blocks `/dev/kvm` for `untrusted_app`, `QemuCommandBuilder` defaults to `-accel tcg,thread=multi,tb-size=128`. KVM is used strictly when `/dev/kvm` is verified R/W accessible AND the guest is `aarch64`. **x86-64 guests on ARM64 hosts ALWAYS use TCG emulation** and are explicitly labeled non-native speed. [QEMU research](research/QEMU_RESEARCH.md) · [Android virtualization research](research/ANDROID_VIRTUALIZATION_RESEARCH.md)
- **Rootless `libslirp 4.9.7` networking & loopback-only control plane.** TAP/bridge networking requires root/`CAP_NET_ADMIN`; Phase 5 uses QEMU `-netdev user` (`user_slirp`, `isolated_slirp` with `restrict=on`, or `disabled`), binds all VNC, QMP, and `hostfwd` sockets strictly to `127.0.0.1`, blocks privileged host ports `< 1024`, and disables default host-folder sharing (`-nodefaults`, `--enable-virtfs=no`). [VM networking](VM_NETWORKING.md) · [VM security](VM_SECURITY.md)
- **Atomic QCOW2 v3 / RAW storage, SHA-256 verified snapshots & PID-reuse-safe supervision.** `VmStorageManager` implements pure-Rust QCOW2 v3 creation (with `qemu-img` integration), grow-only resizing, SHA-256 import/export, and `.part` staging cleanup. `VmSnapshotManager` supports QMP/`qemu-img` internal QCOW2 snapshots plus SHA-256 verified offline snapshots. `QemuSupervisor` verifies `/proc/<pid>/stat` `starttime` ticks before signaling during bounded ACPI-to-SIGKILL shutdown. [VM storage](VM_STORAGE.md) · [VM management](VM_MANAGEMENT.md)
- **Stage 3.2 display reuse & official-only image catalog.** QEMU VNC (`127.0.0.1:5910+`) with `virtio-gpu-pci`/`virtio-vga` + `usb-tablet`/`usb-kbd` connects directly into the existing Stage 3.2 `ANativeWindow` RFB viewport (`DisplayViewportScreen.kt`). `VmImageCatalog` links strictly to official upstream HTTPS portals and SHA-256 feeds without bundling copyrighted OS images or proprietary firmware. [VM display](VM_DISPLAY.md)

## Phase 4 (4.2–4.9) — Complete Windows Compatibility Engine

- **Wine `11.0` x86-64 pure-64-bit WoW64 over Box64 `v0.4.4`.** Selected upstream Wine `11.0` (LGPL-2.1-or-later) pure-64-bit WoW64 executed via Box64 (`rust/crates/wine`) so both PE32 (`i386`) and PE32+ (`x86_64`) Windows apps run inside a single `WINEARCH=win64` prefix without Box86 or 32-bit Linux multilib dependencies (which fail on 64-bit-only ARMv9 SoCs like Xiaomi Pad 7). [Wine research](research/WINE_RESEARCH.md)
- **Six-stage honest graphics readiness model.** `androidpc-graphics-backend` strictly separates `NotInstalled`, `Installed`, `Detected`, `Initialized`, `Operational`, and `ActiveInApp`. Placing a `.so` file on disk never elevates a backend to `Operational`; hardware selection requires a live verified probe, falling back automatically to Mesa `llvmpipe` software rendering with an explicit reason. [Graphics backends](GRAPHICS_BACKENDS.md)
- **Turnip (`26.3.1`) vs. VirGL (`1.3.0`) capability separation.** Mesa Turnip targets Qualcomm Adreno GPUs (`/dev/kgsl-3d0`, Xiaomi Pad 7 Adreno 732) for Vulkan 1.3+ + Zink OpenGL. VirGL (`virglrenderer 1.3.0` over `virpipe`/`vtest` Android EGL/GLES) is explicitly marked OpenGL-only (`supports_vulkan = false`, `dxvk_compatible = false`, `vkd3d_compatible = false`) and is never presented as a Vulkan/Turnip substitute. [Turnip research](research/TURNIP_RESEARCH.md) · [VirGL research](research/VIRGL_RESEARCH.md)
- **Strict DXVK (`v2.7.1`) & VKD3D-Proton (`v3.1`) capability gating.** DXVK activates only on an `Operational` Vulkan 1.3+ backend with staged DLLs; otherwise `DxTranslationManager` falls back to `WineD3D` OpenGL. VKD3D-Proton additionally requires live verification of all 6 mandatory Vulkan extensions (`VK_KHR_dynamic_rendering`, `VK_EXT_descriptor_indexing`, `VK_KHR_buffer_device_address`, `VK_KHR_timeline_semaphore`, `VK_EXT_robustness2`, `VK_EXT_extended_dynamic_state`). [DXVK research](research/DXVK_RESEARCH.md) · [VKD3D research](research/VKD3D_RESEARCH.md)
- **Auditable dependency management & scoped process cleanup.** `androidpc-dependency-manager` separates SHA-256 verified open-source artifacts from user-supplied official installers for proprietary Microsoft runtimes (no blind `curl | sh` or bundled proprietary binaries). Process cleanup (`androidpc-wine` + `androidpc-core`) scopes `wineserver -k`/`-k9` strictly to the target isolated `WINEPREFIX`. [Dependency management](DEPENDENCY_MANAGEMENT.md) · [Process lifecycle](PROCESS_LIFECYCLE.md)

## Phase 4.1

- **Pure-Rust ELF inspection & explicit Box64 routing.** `androidpc-box64` (`rust/crates/box64`) parses ELF headers, `PT_INTERP`, and `SHT_DYNAMIC`/`DT_NEEDED` directly in Rust before executing binaries inside PRoot. ARM64 (`EM_AARCH64`) binaries execute natively without Box64, `EM_X86_64` ELF64 binaries route through Box64 with per-environment configuration, and unsupported architectures or Bionic-linked binaries fail with structured diagnostics rather than blind wrapping or root-only `binfmt_misc`. [Compatibility architecture](research/ARM64_X86_COMPATIBILITY.md)
- **Strict glibc vs. Bionic ABI separation.** Box64 `v0.4.4` (MIT) is cross-compiled for `aarch64-linux-gnu` (guest Linux glibc) via `scripts/build_box64_arm64.sh` (`-DARM64=1 -DARM_DYNAREC=ON -DBAD_SIGNAL=ON -DBOX32=OFF -DCMAKE_BUILD_TYPE=RelWithDebInfo`), never linked against Android NDK Bionic, and staged inside `<guest_rootfs>/usr/local/bin/box64`. `Box64EnvironmentConfig` rejects Android/Bionic library paths and strips host `LD_PRELOAD`. [Box64 Android build pipeline](research/BOX64_ANDROID_BUILD.md)
- **Conservative per-environment defaults.** Box64 settings live per environment (`EnvironmentConfig::box64`) with `BOX64_DYNAREC=1`, `SAFEFLAGS=1`, `STRONGMEM=1`, `BIGBLOCK=1`, `BOX64_LOG=1` (Errors), and `BOX64_SHOWSEGV=1` / `BOX64_SHOWBT=1`. Experimental Dynarec flags are never enabled automatically, and Interpreter fallback (`BOX64_DYNAREC=0`) is exposed directly in the Compatibility UI. [Box64 research](research/BOX64_RESEARCH.md)
- **Star Plus container-centric Android UI.** Redesigned the Android Compose shell around a dark obsidian/starlight theme, bundled Space Grotesk / Inter / JetBrains Mono typography, `ModalNavigationDrawer` with `BackHandler` support, container-first dashboard cards, and a dedicated `CompatibilityScreen` exposing Box64 status, simple enable/mode controls, collapsed advanced settings, ELF runner, and Categories A–D test suite.

## Stage 3.2

- **Built-in viewport.** RFB decodes into one CPU framebuffer. The Rust presenter copies a dirty generation directly into a checked ANativeWindow buffer. Canvas provides compatibility on the same transport. Android manages surface creation, destruction and producer coordination. [Architecture decision](research/DISPLAY_ARCHITECTURE_DECISION.md#stage-32-decision)

## Stage 3.1

- **APT source migration.** The guest package architecture and release gate a rewrite of recognized Ubuntu archive URLs. Ubuntu suites, components, signing options, and third-party mirrors remain under guest control. The first original is recoverable beside each changed file. [Guest APT research](research/ANDROID_LINUX_RESEARCH.md#stage-31-guest-package-sources)
- **Desktop lifecycle.** Rust scopes shutdown to the desktop launch that owns the PRoot child. Android activity changes may detach the viewport while the desktop remains available. [Session ownership](research/DISPLAY_ARCHITECTURE_DECISION.md#stage-31-session-ownership)
